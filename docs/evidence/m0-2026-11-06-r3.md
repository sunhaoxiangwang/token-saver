## Notes

- Both Claude Code manifests show `inbound_outcome: running`: Claude Code stops the server with a
  signal rather than by closing stdin, so the relay's stdin was still open when the forwarded signal
  ended the child. A signal-driven end with no input failure is orderly; any framing, read, or
  forwarding failure would have recorded a different outcome and made the run incomplete.
- Claude Code selected the v1 runtime in run 1 and the v2 runtime in run 2 with identical
  configuration; the compatibility table now records both observations against this binary.
- A first Codex run against this binary succeeded, but its log extraction was over-broad (it
  captured configuration lines); it was discarded, its relay files archived outside the pack, and
  the run repeated with a precise extraction. Both raw Codex logs contained the account email and
  were hashed and deleted; the hashes are in the index.
